RomM Arcade Field Guide

Tick each box as you go. Help for every step is at the end, by step number. Tabs: eels@cobra-stream (PowerShell tab, SSH to the SGIN) and Browser (your browser on the-box). Everything is done on the-box.

Part 4. Get the cover art and game info keys

Help, by step number

1.1 No arcade pod means the port fix (F11) hasn't run yet, and RomM can't start: RomM and Kavita both use port 5000 inside the shared stream pod. Do Part 4 of the v3.6 run list (V:\=ClaudeCode=\cobra-runlist-2026-11-21-v3.6.zip) or the Thanksgiving fix list first. If it ends with "The setup wizard is ON", go straight to Part 3 here. Then come back to 1.2.

1.2 If there is no romm.container, RomM was started with the scripts/podman scripts instead. Stop and send a screenshot of 1.1 and 1.2; Part 5 is different there.

1.3 romm keeps restarting (the STATUS says Up 3 seconds each time): send a screenshot of 2.8's output.

1.4 If you would rather keep the old RomM data and only get back in: on the RomM sign-in page click Forgot your password?, type the admin username, then run 2.8's log command and look for Reset link:. Copy everything from /reset-password?token= to the end, and open https://arcade.songofeo.com plus that part. It works once, within 10 minutes. The host in the logged link says 0.0.0.0 until step 5.3 sets ROMM_BASE_URL.

2.2 File exists: an earlier reset used that name. Use romm.pre-reset-2026-11-27b here and in 2.4. Undo the whole Part 2: stop both (2.1), move the new /srv/stream/romm aside, move romm.pre-reset-2026-11-27 back to /srv/stream/romm, start both (2.5, 2.7).

2.4 config.yml holds the cabinet's folder map and the netplay switch. If there wasn't one, RomM uses its defaults and Part 6 still works. The old database stays in the pre-reset folder until you delete it yourself.

2.6 MariaDB sets itself up the first time, so ready for connections can show twice. That's normal. RomM reaches it at 127.0.0.1:3306 inside the arcade pod, with the user romm and the password already written in romm.container and romm-db.container. A new empty database simply takes that same password.

2.8 Address in use means the port 5000 clash is back (Help 1.1). Can't connect to means MariaDB wasn't ready: run 2.7 again, using restart in place of start.

3.1 RomM sees the folder /srv/storage/disks/dock1b/roms as roms/, one folder per platform (snes, n64, arcade and so on). Will create would make empty folders there; leave it off. "No library structure detected" means dock1b isn't mounted or is empty: send a screenshot of the wizard and stop here.

3.3 Using the same username and password as the gate keeps the station pass working: one set of details for every app.

4.1 IGDB (Twitch's game database) needs a Twitch account with two-step login turned on: Twitch → Settings → Security and Privacy → Set Up Two-Factor Authentication.

4.2 The name must be unique on Twitch. A name someone already used fails with no message, so use random letters.

5.2 If the file already has lines, keep them, and only add the ones from 5.3 that are missing. A line that is there twice uses the last one.

5.3 What each line does:

LineWhat it does
IGDB_…Names, descriptions, covers, screenshots, related games.
SCREENSCRAPER_…Covers, 3D boxes, manuals. Strong on arcade and older consoles. Free account; a free account is slower at busy times.
STEAMGRIDDB_API_KEYNicer alternative cover art.
RETROACHIEVEMENTS_API_KEYAchievements tab per game. Each player adds their own RetroAchievements username in their RomM profile.
HASHEOUS_API_ENABLEDMatches games by file fingerprint, no key needed. Catches badly named files.
LAUNCHBOX_…The same game database as LaunchBox on the cabinet, refreshed daily at 09:00 UTC.
ENABLE_SCHEDULED_RESCAN, SCHEDULED_RESCAN_CRONA Quick scan every day at 12:00 UTC (early morning in the US), after the cabinet's 3:30 am copy to dock1b. RomM's clock is UTC.
ROMM_BASE_URLMakes password-reset links point at arcade.songofeo.com.

5.6 BIOS files need their own folder outside roms/. Without the 5.11 line, uploaded BIOS files lived inside the container and vanished at every restart or update. dock1b/bios sits beside dock1b/roms, so it is kept with the ROMs. The cabinet's nightly copy only adds files, so it never removes these.

5.9 The backup goes next to the folder, not into it, so the container system doesn't read it as a second RomM. Undo 5.11: copy the backup back over romm.container, then 5.13 and 5.14.

5.11 If the Thanksgiving fix list switches RomM to the romm.sh script later, the keys file still works (the script reads ~/.config/cobra/romm.env by itself). The BIOS folder line must be added to the script then.

5.15 API key invalid: a key was pasted with a space or a missing character. Fix it with 5.2 to 5.4, then 5.14. API key missing on all of them: the EnvironmentFile= line is missing or misspelled (5.10).

6.3 The scan types:

Scan typeWhen to use it
New platformsYou added a whole new platform folder. Fastest.
Quick scanNew games in folders RomM already knows. The daily scan uses this.
Unmatched gamesGames with no cover or name yet, or after adding a new key.
Update metadataRefresh info for games that are already matched.
Recalculate hashesRarely: after a file was replaced with the same name.
Complete rescanRarely: wipes all matches and starts over (saves are kept). Slowest.

6.4 Expect about 4 seconds per game. A platform under the wrong name or not found: https://arcade.songofeo.com/library-management → Folder mappings → Folder aliases, map the cabinet's folder name to the RomM platform, then a New platforms scan. Games still without covers after 6.5: rename the file to its proper title (for example Super Metroid (USA).sfc) on the cabinet's D:\Roms, wait for the nightly copy, then run Unmatched games.

7.1 Play needs https, so always use arcade.songofeo.com, not 10.6.9.20:8080. PSP and a few heavy systems refuse to start over plain http. Keyboard keys and controller buttons are set in the player's own menu → Controls. Slow or stuttery: close other tabs, or pick a lighter core in the player menu → Core (snes9x rather than bsnes). Picking a new core makes old save states unusable; normal in-game saves still work.

7.3 In-game saves upload to RomM a few seconds after the game writes them, and follow you to any browser where you sign in as yourself. Save states (the player's quick-save) also upload, but they only load in the same core. Each player only sees their own saves. Netplay (playing together in the browser) is off unless config.yml turns it on, and the RomM team says it is unstable right now; it works best with everyone at home.

8.2 No such file or directory: step 5.11 wasn't saved or 5.14 didn't run, so the upload went into the container. Do 5.10 to 5.14, then upload again.

9.1 Or click Invite link, pick Role: User and an expiry, click Generate, and send the link: they pick their own username and password (use the same as their gate sign-in). Viewer lets a player browse, play and keep their own saves and collections; Editor also lets them edit games and upload ROMs. To hide platforms from one player (for example for kids): edit the user → Access.

9.3 The gate signs people in once, then RomM asks for its own login the first time on each device and remembers it.

MariaDB (romm-db)Same pod, /srv/stream/romm/dbAccounts, games found, play history, save records

Saves and states/srv/stream/romm/assetsEvery player's saves, per game

BIOSdock1b/biosConsole BIOS files
ScoreboardGate, scores.songofeo.comCabinet high scores (.hi files from RetroArch/MAME). Browser games in RomM don't write .hi files, so they don't reach the board. The High Scorers Lounge (being built separately) will join RomM's "latest played" with the board.
